# 동작 계약

[English](../behavioral-contracts.md) | 한국어

제너레이터 16종 모두 아래 계약을 따르고, 테스트로 확인해요.

## 쓰기

- **`--dryRun`은 전부 미리 보여주고 아무것도 쓰지 않아요.** `init`도 마찬가지예요. dry-run에서는 init의 실행 후 검증 콜백도 동작하지 않아요.
- **다시 실행해도 바뀌는 게 없어요.** 기존 내용과 완전히 같으면 제너레이터는 다시 쓰지 않고 "변경 없음"으로 보고해요.
- **제너레이터 단위로 원자적이에요.** 제너레이터는 의도한 변경 집합을 전부 적용하거나, 중단을 보고해요. 서브 제너레이터가 예기치 않게 throw하면 `init`은 그 에러를 aborted 섹션으로 접어요. 그래서 나머지 파이프라인도 끝까지 보고해요.

## 거부는 예외가 아니라 리포트

아래 4가지 경우에는 제너레이터가 throw하지 않고, 구조화된 거부 리포트로 이유를 알려줘요.

- 더러운 트리
- 프론트엔드 앱이 없거나 2개 이상
- 본질로 지은 세그먼트 이름(`components`, `hooks`)
- 사용할 수 없는 public API 이름

## 충돌을 조용히 덮어쓰지 않아요

기본 정책은 `merge-proposal`이에요. 제너레이터 3개는 충돌을 이렇게 처리해요.

| 제너레이터 | 충돌 시 |
| --- | --- |
| `add-agent-rules` | 자기 표시 블록만 기록(아래 참고) |
| `add-github-templates` | 항상 건너뜀 |
| `add-review` | 명시적 `--onConflict` 값을 따름 |

- `add-agent-rules`는 `CLAUDE.md` / `AGENTS.md` 안에서 자기 표시 블록만 쓰고, 블록 주변 내용은 쓰지 않아요. 표시를 안전하게 놓을 수 없으면 추측하지 않고 보고해요.
- `add-review`의 `--onConflict`는 3가지 값 중 하나를 받아요: `overwrite` / `skip` / `alternate-filename`.

## 출력과 검증

- **리포트는 영어, 콘텐츠는 로케일.** CLI·리포트 출력은 항상 영어예요. `--locale`은 생성 파일에만 영향을 줘요.
- **Best-effort 검증은 그렇다고 명시해요.** 실제 `init` 실행 후에 init이 `actionlint`와 `nx graph`를 preflight 검사와 함께 호출해요.

> [!NOTE]
> **도구가 없어도 실패가 아니에요.** `actionlint`나 `nx graph`를 쓸 수 없으면 실패가 아니라 *설치 안내와 함께 skip*으로 보고해요.
